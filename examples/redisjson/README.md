# Redis JSON examples

This example exercises both Redis interaction styles generated by `NSmithy.Bote`:

- `chat` models a durable command stream and a separate event stream. Posting a
  message is one-way; clients follow `MessagePosted` events independently.
- `inventory` models unary request/reply. Requests are durable Redis Stream entries,
  while each reply is delivered over a temporary correlated Pub/Sub channel.

Build locally packed packages first, then start Redis:

```bash
just pack
docker compose -f examples/redisjson/docker-compose.yml up -d
```

Run the chat example:

```bash
dotnet run --project examples/redisjson/chat
```

The process asks for your display name and joins the `lobby` room. Press Enter
at the name prompt to use your local user name. Type messages at the chat prompt
and press Ctrl+C to stop. Optional arguments select the Redis endpoint, room,
and display name without prompting:

```bash
dotnet run --project examples/redisjson/chat -- localhost:6379 engineering alice
```

Run the request/reply server in one terminal:

```bash
dotnet run --project examples/redisjson/inventory/server
```

Then perform a lookup from another terminal:

```bash
dotnet run --project examples/redisjson/inventory/client -- localhost:6379 coffee-beans
```

The server and client share the inventory contracts project. The server keeps its generated durable request consumer
running until Ctrl+C. The client sends one request, receives the correlated reply,
and exits. Chat keeps its model and both roles in one project because its focus is
the interactive command/event stream rather than deployment topology.
