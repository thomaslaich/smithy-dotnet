## How the numbers are counted

Each fraction is:

```text
passing executable official cases / official cases applicable to that surface
```

Client and server totals are separate because Smithy test cases declare an
`appliesTo` direction. A server-only case does not enter the client denominator,
and a client-only case does not enter the server denominator.

Cases listed in a conformance project's known-gap set remain in the denominator
but not the numerator. Local regression fixtures run in the suites but do not
count as official conformance.

## Coverage notes

- restJson1 passes every applicable official request, response, modeled-error,
  and malformed-request case on both generated surfaces.
- The restJson1 server passes all 655 applicable
  `httpMalformedRequestTests`. These cases verify structured responses for
  requests that cannot be deserialized or validated.
- Auxiliary fixture services without a generated handler are excluded from the
  restJson1 server denominator. Local response regression cases are also
  excluded from the official totals.
- simpleRestJson passes every case in Alloy's protocol suite on both generated
  surfaces.
- rpcv2Cbor runs the protocol service and the AWS `@awsQueryCompatible` fixture services.
  Its known gaps are query-compatible: the client does not send `x-amzn-query-mode`, the server
  does not send `x-amzn-query-error`, and modeled errors do not expose the error code the client
  cases expect.
- rpcv2Json runs the protocol service, the `RpcV2JsonCorpusTests` corpus, and the AWS
  query-compatible corpus services. Its known gaps are the same query-compatible ones as
  rpcv2Cbor's, document values, discriminated unions, blobs nested in lists and maps, `bigDecimal`
  beyond C# `decimal` precision, and a few runner limitations (idempotency tokens, request
  compression, empty bodies). The official suite has no event-stream cases; JSON event streams
  are covered by unit tests.
- AWS Query and EC2 Query pass every applicable official client request case. Their known
  response gaps are modeled errors whose fixtures expect an error code, which modeled errors do
  not expose.
- restXml passes every applicable official client response case. Its known request gaps are S3
  cases that configure the client (region, addressing style, dual-stack, accelerate), which the
  runner does not apply yet.
- AWS JSON 1.1 passes every applicable official client request and response case.
- AWS JSON 1.0 passes every applicable official client request case. Two response cases are
  known gaps: modeled errors of `@awsQueryCompatible` services do not expose the awsQuery error
  code that `x-amzn-query-error` carries.
- The endpoint rules fixtures are the `smithy-rules-engine-tests` models, the
  `aws.*` function test models of `smithy-aws-endpoints`, and the published
  models of five AWS services chosen for their built-ins and auth scheme
  properties.
- gRPC is not part of Smithy's HTTP protocol test suite. Its codec and transport
  tests cover complex messages, numeric encodings, collections, oneofs,
  documents, errors, trailers, and all three streaming modes. Grpc.Net
  interoperability is demonstrated by runnable examples but is not yet an
  automated cross-implementation test matrix.

See [Validation](/smithy-dotnet/servers/validation/) for malformed request
behavior.

## Maturity labels

- <Badge text="Stable" variant="success" /> every applicable official conformance case
  passes on every generated surface, and the generated API changes only with
  care for existing users.
- <Badge text="Preview" variant="note" /> useful end-to-end support with meaningful conformance coverage.
  Some protocol features or convenience APIs are still incomplete, and the generated API can
  still change.
- <Badge text="Early preview" variant="caution" /> a narrower verified slice. Check the conformance totals and
  known limitations before adopting it.
- <Badge text="Experimental" variant="danger" /> the API and supported model surface can still change.

## Reproducing the report

Each conformance project has a
`ConformanceRateTests.ReportConformanceRate` test. Run it after `just codegen`
and copy the emitted totals to this page.

The fixtures come from the pinned Smithy and Alloy protocol-test model JARs.
The upstream restJson1 sources are in the [Smithy
repository](https://github.com/smithy-lang/smithy/tree/main/smithy-aws-protocol-tests/model/restJson1).
