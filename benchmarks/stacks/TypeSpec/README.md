# TypeSpec stack

MVC controllers generated by `@typespec/http-server-csharp` 0.58.0-alpha.33
from the Smithy-emitted OpenAPI document, hosted the way the emitter's own
`Program.cs` hosts them. The host pins the JSON encoder to
`JavaScriptEncoder.Default` so non-ASCII is escaped like every other stack.

## Regenerating

```sh
npm install
npm run import     # OpenAPI 3 -> tsp/, via tsp-openapi3
npm run generate   # tsp/ -> emitted/, via @typespec/http-server-csharp
```

`tsp/` and `emitted/` are committed so the suite builds without Node. Never
edit them. `emitted/Program.cs` and `emitted/docs/` are not compiled.
`@typespec/compiler` 1.17.0 resolves `@alloy-js` 0.24 while the emitter needs
0.25, and the emitter fails to load with both present; the `overrides` block in
`package.json` pins 0.25.

## Unserved scenarios

The stack is compared on `get-item-hit`, `list-items-1`, `list-items-100` and
`list-items-10000`. The rest are declared unserved in `BenchStacks`, and the
parity gate fails if the emitter ever starts serving one of them:

- `search-items`: the `x-total-count` response header is emitted as a body
  property of a wrapper model, and the controller returns `Ok(result)`. Nothing
  in the output writes a response header except the exception filter.
- `create-order-small`, `create-order-large`, `get-item-miss`: the status code
  is emitted as a `statusCode` body property.
- `validation-range`, `validation-multi`: constraints on query parameters are
  not enforced, so the request reaches the handler.
- `validation-length`, `validation-pattern`: constraints on models are JSON
  converters that throw `JsonException`. On a request body MVC turns that into
  problem details; on a response body it is unhandled. Neither is the modeled
  `ValidationException`.

The header and status-code problems are visible in
`emitted/generated/models/*Response.cs` without running anything.
